# NC Daily Blooms

A complete flower shop with a Next.js frontend, a separate Node.js / Express API, and MongoDB persistence. The storefront uses the yellow and teal theme, the approved NC Daily Blooms logo, generated flower photos, and English / Kannada copy.

## Included

- Flower collection, category filters, availability, shopping bag, delivery form and WhatsApp enquiry.
- Customers register with a 10-digit Indian phone number. The API generates a permanent four-digit PIN and displays it once. Future logins use the same phone and PIN.
- Customer accounts show only their own orders, quotes and delivery updates. A customer accepts a quote to confirm an order.
- One admin account at `/admin`, with order status / quotation management, product management, customer list and PIN reset.
- Hashed PINs, opaque cookie sessions, login rate limits, origin checks, input validation and idempotent order submission.
- MongoDB indexes, automatic initial catalog seeding and persistent data across restarts. PIN resets invalidate all previous customer sessions.

No SMS is sent, and registration does not verify phone ownership. No online payment is collected; final prices and delivery charges are confirmed by the shop. Some flower images are illustrative.

## Run locally

Requires Node.js 22.13 or newer, npm, and MongoDB. Docker is optional.

```bash
npm ci
npm run setup
```

The setup script asks for a MongoDB URI and admin PIN. Press Enter to use local MongoDB, then enter your private four-digit admin PIN. It saves a hash in the ignored `backend/.env`; the PIN is not sent to frontend code. It also creates `frontend/.env.local`.

Start local MongoDB with Docker, or use a running MongoDB instance / Atlas URI:

```bash
docker compose up -d
npm run dev
```

Open <http://localhost:3000>. Customer orders: `/account`. Single admin: `/admin`. API: <http://127.0.0.1:4000/api/health>.

Always run root commands from the repository root. The setup script preserves existing environment files. If `.env` already exists, edit it directly; do not overwrite it with an empty example.

## Checks and production start

```bash
npm test
npm run typecheck
npm run build
npm start
```

Tests use an isolated real MongoDB process through `mongodb-memory-server`; the first run downloads a MongoDB binary. They do not connect to your configured shop database. Tests cover permanent PIN login, admin access, cookie settings, rate limits, order validation / ownership / retries, quotes, catalog changes, PIN reset, expiry and logout.

`npm run build` builds the actual Next.js application. `npm start` runs the built frontend and Node API together.

## Deployment configuration

Deploy `frontend/` as Next.js and `backend/` as a long-running Node service. Connect the backend to your own MongoDB database; no production customer data or secrets are included in this repository.

| Location | Variable | Purpose |
| --- | --- | --- |
| Frontend | `API_BASE_URL` | Internal API origin, e.g. `https://your-api.example.com`. Configure before building: Next.js embeds the rewrite target in its build. |
| Backend | `MONGODB_URI` | MongoDB connection URI including the database name. |
| Backend | `ADMIN_PIN_HASH` | Hash generated by `npm run setup`; keep this secret. |
| Backend | `FRONTEND_URL` | Exact public frontend origin, e.g. `https://your-shop.example.com`. |
| Backend | `NODE_ENV` | `production` for deployment, enabling Secure cookies. |
| Backend | `PORT` | API listen port, default `4000`. |
| Backend | `TRUST_PROXY_HOPS` | Exact number of trusted proxy hops, default `0`. Configure to your host's proxy topology so IP limits work correctly. |

Browser requests use same-origin `/api/*` calls. Next.js forwards them to the API, keeping HttpOnly sessions on the frontend origin. Use HTTPS in production, keep MongoDB credentials in your host's secret configuration, and keep the API behind the intended trusted proxy. Never blindly trust arbitrary forwarded IP headers.

Catalog seeding inserts only missing defaults and does not restore products removed by the admin. Money values in the API are integer paise. Quotes include delivery. This is a fresh MongoDB implementation; it does not migrate records from the earlier hosted preview.
